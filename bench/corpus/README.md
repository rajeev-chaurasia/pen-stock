# The cache quality corpus

`questions.json` is the ground truth for `cmd/cachestudy`. Every number
in `docs/cache-quality.md` comes from running that command against this
file.

## Why it is hand written

The study asks whether a semantic cache serves the right answer. To
answer that you need to know, for each request, whether a hit would have
been correct. There are two ways to get that.

The usual way is to replay a public dataset of real questions and judge
the hits afterwards, normally by asking a model whether two questions
mean the same thing. That is circular. Deciding whether two questions
mean the same thing is exactly the judgement the cache is being tested
on, so the study ends up measuring the agreement between two models
rather than the correctness of a cache.

The other way is to build the answer in. Every question here was written
as a deliberate transformation of another one, and the transformation is
recorded as the label. Nothing has to be judged at scoring time, because
the judgement happened when the question was written.

That is also why **the corpus must not be generated by a model.** A
model's idea of a paraphrase is the thing under test. Asking it to
produce the test cases would make the corpus agree with the embedder by
construction and the result would mean nothing.

## Schema

```
{
  "schema": "penstock/cache-quality/corpus/v1",
  "note":   "...",
  "groups": [ Group, ... ]
}
```

**Group**

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Unique within the file. Identifies which answer came back on a hit. |
| `domain` | string | Subject area. Used only to show the corpus is not all one topic. |
| `anchor` | string | The question a warm cache already holds the answer to. |
| `probes` | array | The traffic that arrives afterwards. |

**Probe**

| Field | Type | Meaning |
|---|---|---|
| `label` | string | One of `repeat`, `paraphrase`, `opposite`, `unrelated`. |
| `text` | string | The question sent. |
| `flip` | string | Required on `opposite`. Names the word that was changed. |

## The labels

| Label | Construction | A hit is |
|---|---|---|
| `repeat` | The anchor resent, byte for byte. | **Correct.** This is what the exact tier is for and it needs no embedder. |
| `paraphrase` | The same question reworded, written so the anchor's answer serves it unchanged. | **Correct**, and only when the answer comes from its own group. |
| `opposite` | The anchor with one word flipped so it asks the reverse thing. | **A false hit.** This is the number the study exists to publish. |
| `unrelated` | A question from a different subject entirely. | **A false hit**, and the floor. A cache that hits here is not similar-but-wrong, it is broken. |

The flips used are the ordinary ones an operator types every day:
enable/disable, start/stop, safe/unsafe, use/avoid, should/should not,
include/exclude, allow/block, inbound/outbound, mount/unmount,
grant/revoke, upgrade/downgrade, public/private, required/optional,
encode/decode, compress/decompress, mutable/immutable,
exported/unexported, increase/decrease, longer/shorter, raise/lower.

## Rules the loader enforces

`cmd/cachestudy` refuses a corpus that breaks any of these, because each
one protects a claim the study makes later.

- The schema string matches exactly.
- Group ids are unique.
- **Every question text in the file is unique**, anchors and probes
  alike. A text shared by two groups would have two correct answers, so
  a hit on it could not be scored.
- Each group has **exactly one** `repeat`, and its text is byte
  identical to the anchor. A repeat that is not byte identical is a
  paraphrase wearing the wrong label, and the exact tier's 100 percent
  would then be measuring something else.
- Each group has at least one `paraphrase`, one `opposite` and one
  `unrelated`. A group without an opposite contributes nothing to the
  only number that matters.
- Every `opposite` records its `flip`, so a reader can check the label
  rather than trust it.

## What would make this corpus misleading

1. **Paraphrases that are not really interchangeable.** If a paraphrase
   asks a subtly different question, a correct refusal is scored as a
   miss and the paraphrase hit rate is understated. These were written
   to be interchangeable, but that is a judgement made by one person and
   it is the softest part of the study.

2. **Opposites that are not really opposite.** If a flip leaves the
   answer substantially the same, a hit on it is scored as a false hit
   when it was harmless. `flip` is recorded on every one so this is
   checkable.

3. **Sentence length.** These are short single-turn questions. A real
   prompt often carries a system message, a document, and several turns,
   all of which are shared between an anchor and its opposite. That
   would push every similarity up and make the separation worse, not
   better, so the numbers here are the optimistic case.

4. **English only, and one register.** Every question is a plain English
   question written by one author. A corpus with more variety in phrasing
   would likely spread the paraphrase scores wider.

5. **One question per group in the warm cache.** The study warms the
   cache with anchors only. A production cache holds thousands of
   unrelated entries, which gives an incoming question far more chances
   to find a spurious neighbour than it has here.
